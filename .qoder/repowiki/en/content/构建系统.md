## 构建系统概述

MySQL Server 使用 **CMake**（最低版本 3.17.5）作为构建系统。根目录下的 [CMakeLists.txt](file://CMakeLists.txt)（约 2935 行）编排整个构建过程，包括平台检测、编译器配置、特性检测和构建目标定义。`cmake/` 目录中的 CMake 模块处理特定子系统：SSL 检测（`ssl.cmake`）、Boost 集成（`boost.cmake`）、Protobuf（`protobuf.cmake`）、ICU（`icu.cmake`）、Bison 语法生成（`bison.cmake`）等。

构建产出的主要制品包括：
- **mysqld** — MySQL 服务器守护进程
- **mysqlrouter** — MySQL 路由器（中间件）
- **客户端工具** — mysql、mysqldump、mysqladmin、mysqlbinlog 等
- **libmysqlclient** — 客户端共享/静态库
- **插件** — 动态插件共享库（.so/.dll）
- **组件** — 动态组件共享库

## 平台要求

| 平台 | 最低版本 | 编译器 | CMake 最低版本 |
|------|---------|--------|---------------|
| Linux (RHEL) | 6–10 | devtoolset-11 (RHEL7)、gcc-toolset-14 (RHEL8/9)、gcc-13 (SUSE 15) | 3.17.5 |
| macOS | 11+ | Apple Clang (Xcode) | 3.19（Xcode 构建） |
| Windows | 10 / Server 2016+ | Visual Studio 2019+ (MSVC) | 3.17.5 |
| Solaris | 11 | GCC 11 | 3.17.5 |

构建系统通过 `cmake/os/` 平台模块自动检测编译器工具链。在 RHEL 系统上，它会探测 devtoolset/gcc-toolset 安装路径。如需使用不受支持的编译器，需要添加 `-DFORCE_UNSUPPORTED_COMPILER=ON` 选项。

## CMake 配置与构建流程

标准构建命令：

```bash
# 配置（生成构建文件）
cmake -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo .

# 编译（并行构建）
cmake --build build -j$(nproc)

# 安装
cmake --install build --prefix /usr/local/mysql
```

Windows 平台构建命令：

```powershell
# 配置
cmake -B build -G "Visual Studio 17 2022" -DCMAKE_BUILD_TYPE=RelWithDebInfo .

# 编译
cmake --build build --config RelWithDebInfo

# 安装
cmake --install build --config RelWithDebInfo --prefix C:\mysql
```

默认构建类型为 `RelWithDebInfo`（带调试信息的优化版本）。设置 `-DWITH_DEBUG=ON` 可启用调试构建，开启断言和 DBUG 跟踪。

## 关键构建选项

### 核心选项

| 选项 | 默认值 | 说明 |
|------|--------|------|
| `CMAKE_BUILD_TYPE` | RelWithDebInfo | 构建类型：Debug、Release、RelWithDebInfo |
| `WITH_DEBUG` | OFF | 启用调试构建（dbug/safemutex） |
| `MAX_INDEXES` | 64U | 每表最大索引数（上限 255） |
| `WITH_SSL` | system | OpenSSL 路径或 "system"（使用系统安装） |
| `WITH_ROUTER` | ON | 是否构建 MySQL Router |

### 存储引擎选项

| 选项 | 默认值 | 说明 |
|------|--------|------|
| `WITH_INNOBASE_STORAGE_ENGINE` | ON | 包含 InnoDB 存储引擎 |
| `WITH_MYISAM_STORAGE_ENGINE` | ON | 包含 MyISAM 存储引擎 |
| `WITH_NDB` | OFF | 构建 MySQL Cluster (NDB) 支持 |

### 调试与分析选项

| 选项 | 默认值 | 说明 |
|------|--------|------|
| `WITH_ASAN` | OFF | 启用 AddressSanitizer（内存错误检测） |
| `WITH_TSAN` | OFF | 启用 ThreadSanitizer（数据竞争检测） |
| `WITH_UBSAN` | OFF | 启用 UndefinedBehaviorSanitizer（未定义行为检测） |

### 依赖库选项

| 选项 | 默认值 | 说明 |
|------|--------|------|
| `WITH_BOOST` | (自动) | Boost 库路径 |
| `WITH_PROTOBUF` | bundled | Protobuf 来源："bundled"（内置）或 "system" |
| `WITH_ICU` | bundled | ICU 来源："bundled"（内置）或 "system" |
| `WITH_CURL` | bundled | curl 来源 |
| `DOWNLOAD_BOOST` | OFF | 自动下载 Boost（未找到时） |
| `WITH_AUTH_*` | ON | 启用特定认证插件 |

## 安装目录布局

安装目录布局由 `cmake/install_layout.cmake` 控制，通过 `-DINSTALL_LAYOUT=<类型>` 选项指定：

| 布局类型 | 说明 |
|---------|------|
| STANDALONE | 自包含安装（源码构建默认） |
| RPM | RPM 包布局 |
| DEB | Debian 包布局 |
| SVR4 | Solaris SVR4 包布局 |
| SGL | MySQL Cluster 布局 |

STANDALONE 布局的关键目录：

```
/usr/local/mysql/
├── bin/              # 可执行文件（mysqld、mysql、mysqladmin 等）
├── lib/              # 共享库和插件
├── include/          # 公共头文件
├── share/            # 字符集、错误消息、初始化脚本
├── support-files/    # 示例配置文件、启动脚本
├── man/              # 手册页
└── docs/             # 文档
```

## 调试构建配置

启用调试构建的命令和效果：

```bash
# 启用调试构建
cmake -B build-debug -DWITH_DEBUG=ON .

# 调试构建启用以下特性：
# - DBUG 跟踪框架（DBUG_ENTER/DBUG_RETURN 宏）
# - 安全互斥锁（safemutex）检测
# - 断言检查
# - 内存分配跟踪
```

调试构建会显著影响性能（约 30-50% 性能下降），但提供了丰富的调试能力：
- DBUG 跟踪可输出函数调用链
- 内存分配追踪帮助发现内存泄漏
- 断言在违反前提条件时立即中断
