## Performance Schema 概述

Performance Schema（PFS）是 MySQL 内置的性能监控和诊断引擎，以存储引擎的形式实现（`storage/perfschema/`），通过 `PERFORMANCE_SCHEMA` 数据库暴露服务器运行时指标。它使用低开销的插桩方式采集等待事件、阶段事件、语句事件、内存使用、元数据锁等维度的数据，是数据库性能调优和问题诊断的核心基础设施。

Performance Schema 拥有 **163 个源文件**，提供 **90+ 张监控表**，覆盖了 MySQL 服务器几乎所有的内部活动。

## 监控事件类型

PFS 采集多种类型的运行时事件：

| 事件类型 | 说明 | 表前缀 |
|---------|------|--------|
| **等待事件（Waits）** | 互斥锁、读写锁、条件变量、文件 I/O、套接字等待 | `events_waits_*` |
| **阶段事件（Stages）** | 查询执行阶段（如 "Sending data"、"Sorting"） | `events_stages_*` |
| **语句事件（Statements）** | SQL 语句执行的完整信息 | `events_statements_*` |
| **事务事件（Transactions）** | 事务执行的完整信息 | `events_transactions_*` |
| **错误事件（Errors）** | 按账户/主机/用户/线程/全局统计 | `events_errors_*` |
| **内存事件（Memory）** | 各组件的内存分配统计 | `memory_summary_*` |

每种事件类型有三张表：
- `*_current` — 当前活跃的事件（未完成）
- `*_history` — 每线程最近 N 条已完成事件
- `*_history_long` — 全局最近 N 条已完成事件

**Sources** · [storage/perfschema/table_*.cc](file://storage/perfschema/)

| 表 | 说明 |

## PSI 插桩接口

Performance Schema Instrumentation（PSI）通过头文件中定义的宏和函数指针嵌入整个 MySQL 代码库：

### 插桩头文件（include/pfs_*.h）

| 头文件 | 插桩类型 |
|--------|---------|
| `pfs_mutex_provider.h` | 互斥锁 |
| `pfs_rwlock_provider.h` | 读写锁 |
| `pfs_cond_provider.h` | 条件变量 |
| `pfs_file_provider.h` | 文件 I/O |
| `pfs_socket_provider.h` | 网络套接字 |
| `pfs_memory_provider.h` | 内存分配 |
| `pfs_stage_provider.h` | 执行阶段 |
| `pfs_statement_provider.h` | SQL 语句 |
| `pfs_transaction_provider.h` | 事务 |
| `pfs_table_provider.h` | 表访问 |
| `pfs_thread_provider.h` | 线程 |
| `pfs_idle_provider.h` | 空闲等待 |
| `pfs_error_provider.h` | 错误统计 |
| `pfs_metadata_provider.h` | 元数据锁 |
| `pfs_data_lock_provider.h` | 数据锁 |
| `pfs_metric_provider.h` | 度量指标 |
| `pfs_telemetry_logs_provider.h` | 遥测日志 |

### 插桩使用示例

```cpp
// 在代码中使用 PSI 宏进行插桩
mysql_mutex_t mutex;
mysql_mutex_register("module_name", &mutex_info, 1);
mysql_mutex_init(key_mutex, &mutex, MY_MUTEX_INIT_FAST);
mysql_mutex_lock(&mutex);   // 自动记录等待事件
// ... 临界区代码 ...
mysql_mutex_unlock(&mutex); // 自动记录持有时间
```

当 PFS 被禁用时，`mysys/psi_noop.cc` 提供空操作实现，确保零开销。

## 遥测与可观测性

MySQL 9.x 引入了新的遥测服务，由 PFS 引擎实现：

| 服务 | 文件 | 说明 |
|------|------|------|
| 遥测日志 | `mysql_server_telemetry_logs_service_imp.cc` | OpenTelemetry 日志集成 |
| 遥测日志客户端 | `mysql_server_telemetry_logs_client_service_imp.cc` | 客户端侧遥测日志 |
| 遥测度量 | `mysql_server_telemetry_metrics_service_imp.cc`（~23KB） | OpenTelemetry 度量指标采集 |
| 遥测跟踪 | `mysql_server_telemetry_traces_service_imp.cc`（~13KB） | OpenTelemetry 分布式跟踪 |

这些服务使 MySQL Server 原生支持 OpenTelemetry 标准，可以与外部可观测性平台（Grafana、Datadog、Jaeger 等）集成。

**Sources** · [storage/perfschema/mysql_server_telemetry_*.cc](file://storage/perfschema/)

## 诊断与调优

### 启用/配置 PFS

```sql
-- 查看 PFS 是否启用
SHOW VARIABLES LIKE 'performance_schema';

-- 动态启用插桩点
UPDATE performance_schema.setup_instruments
SET ENABLED = 'YES', TIMED = 'YES'
WHERE NAME LIKE 'wait/synch/mutex/%';

-- 启用语句历史记录
UPDATE performance_schema.setup_consumers
SET ENABLED = 'YES'
WHERE NAME IN ('events_statements_history', 'events_statements_history_long');
```

### 常用诊断查询

```sql
-- Top 10 最耗时的 SQL 指纹
SELECT DIGEST_TEXT, COUNT_STAR, AVG_TIMER_WAIT/1000000000 AS avg_ms
FROM performance_schema.events_statements_summary_by_digest
ORDER BY AVG_TIMER_WAIT DESC LIMIT 10;

-- Top 10 等待事件
SELECT EVENT_NAME, COUNT_STAR, SUM_TIMER_WAIT/1000000000 AS total_ms
FROM performance_schema.events_waits_summary_global_by_event_name
ORDER BY SUM_TIMER_WAIT DESC LIMIT 10;

-- InnoDB 锁等待
SELECT * FROM performance_schema.data_lock_waits;

-- 内存使用汇总
SELECT EVENT_NAME, SUM_NUMBER_OF_BYTES_ALLOC
FROM performance_schema.memory_summary_global_by_event_name
ORDER BY SUM_NUMBER_OF_BYTES_ALLOC DESC LIMIT 20;
```

### sys 库

`sys` 库提供了对 Performance Schema 数据的高级封装视图，简化了常见的诊断任务：

```sql
-- 慢查询 Top 10
SELECT * FROM sys.statements_with_runtimes_in_95th_percentile LIMIT 10;

-- 未使用的索引
SELECT * FROM sys.unused_indexes;

-- 冗余索引
SELECT * FROM sys.redundant_indexes;

-- 等待事件分析
SELECT * FROM sys.waits_global_by_latency LIMIT 10;
```
